# 09 没有闭环的地方

读一个项目,知道它没回答什么和回答了什么一样有用。分三类:项目自己承认没查清的,读代码时发现的,以及已知边界。

## 项目没查清的问题

**fc2 异常的根因。** 只拆 fc2 激活的 Q/DQ 时,TensorRT 输出的 SQNR 从约 21 dB 跌到约 3.5 dB,ORT 执行同一张图正常。README 坑 5 的说法是"疑似 TensorRT 10.16 的 Myelin 代码生成缺陷",是黑盒观察,没有证实。复现脚本:`tools/probe_fc2_anomaly.py`。

**INT8 下融合注意力为什么变慢。** 518 档剖析里,融合注意力从 FP16 的 1.55 ms 涨到 INT8 的 2.51 ms,正好吃掉线性层和卷积省下的时间。能看到的事实:INT8 引擎里这个 kernel 输入是 FP16、输出是 INT8,每个 block 后面多一个 `MoveReshTran` kernel。原因没有拆清。

**FP8 引擎"其他"类耗时偏高。** README 说没逐个归类。从 `results/profile_trt.json` 的 `top_kernels` 能看出一部分:最慢的是 DPT 头和颈的卷积(`/model/head/conv2` 在 FP8 引擎里 0.435 ms,在 FP16 引擎里 0.193 ms)。这些卷积在 FP8 引擎里不是 `Cask*` 类型,`11_profile_trt.py` 的 `categorize` 没把它们归进"卷积",所以表里 FP8 的卷积只有 0.09 ms、"其他"有 1.53 ms。它们为什么在 FP8 下更慢,没有查。

## 读代码时发现的

**残差流的校准截断点接近最大值。** `04_activation_stats.py` 的 docstring 假设熵校准会把截断点选在 99.99% 分位附近。实际读 `da2s_r518.int8.onnx` 里的 scale,block 输出处的截断点都贴着 04 统计到的最大值:

| block 输出 | 图里的截断点(scale × 127) | 04 统计的 absmax | 99.99% 分位 |
|---|---|---|---|
| 第 3 个 | 1.87 | 1.9 | 0.25 |
| 第 9 个 | 4.55 | 4.7 | 1.43 |
| 第 10 个 | 13.62 | 13.9 | 1.87 |
| 第 11 个 | 14.81 | 15.4 | 3.31 |

两边的统计样本不同(校准用 200 张,04 用 16 张),但量级一致。modelopt 0.44 的 INT8 校准只有 entropy 和 max 两种选项。把截断点收紧后端到端精度会不会变好,项目没有试过,这里也没有验证。04 的单张量统计显示收紧有好处(block 输出 22.9 → 27.9 dB),但单张量的结论不一定能传到端到端。

**精度统计少数了 5 层。** `trt_utils._COMPUTE_TYPES` 里没有 `CaskJitConv` 和 `CaskDeconvolutionV2`。518 档的 FP16 / INT8 引擎各有 3 + 2 层属于这两类(DPT 颈的卷积和转置卷积),没有计入 README"引擎里实际跑的精度"表。这 5 层的 tactic 精度和其余层一致,表的结论不变。FP8 引擎里对应的是 2 层 `CaskGemmDeconvolution`。

**三处小瑕疵**(根目录 CLAUDE.md 里也有记录):

- `Variant.parse` 不校验 trt 配方名,拼错了要到查表或加载引擎时才报错;
- `tests/` 没有 `__init__.py`,`dl` 环境里用点分路径跑单个测试会失败;
- `07_build_trt.py` 遇到缺失的 ONNX 一律提示"先运行 05",缺的是 int8res / int8mix 时该跑的是 06。

## 已知边界

- **数字只代表这台机器。** GPU 是笔记本 RTX 4060(动态频率);CPU 在 WSL2 里只有 4 个 vCPU,无法绑定物理 P 核。
- **只有 batch = 1、静态形状。** 三档分辨率各一个引擎,没有动态 profile。
- **端到端计时不含取流和显示。** 输入是内存里的一张图。
- **val 只有 100 张。** 逐块回收那一步的单步差异(约 0.0005)接近它的噪声,int8mix 在测试集上没有比 int8res 更好就是这个原因。
- **仿真与真实引擎的"逐图排序不相关"**是 README 坑 4 的记录,`results/` 里只留了均值(ORT 约 15 dB 对引擎 21.5 dB),逐图数据没有落盘。
- **没有 RKNN 栈。** 固定形状和常量折叠是为它铺的路,但没有实测。
- **正文数字是手写的。** `make report` 只刷新 README 里标记之间的表格;README 的结论段落和这组导读里的数字,重跑后都要人工核对。
